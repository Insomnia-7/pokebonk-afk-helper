# PokéBonk 无尽挂机助手

当前发布 **3.1.0**，适配官网 **0.8.59（mvpt1dlr）** 的模块变更，补齐选择策略与完整目录，修复收起后无法展开。

[安装 / 更新脚本](https://raw.githubusercontent.com/Insomnia-7/pokebonk-afk-helper/main/pokebonk-afk.user.js) · [反馈问题](https://github.com/Insomnia-7/pokebonk-afk-helper/issues)

只需安装 **pokebonk-afk.user.js**。meta.js 是油猴检查更新用的文件，不单独安装。

## 安装与启动

1. 在玩游戏的浏览器安装 [Tampermonkey（油猴）](https://www.tampermonkey.net/)，点击上方脚本链接并安装，已有安装则更新。
2. 停用其他版本的挂机脚本，避免同时发送操作。浏览器要求时，按 [油猴权限说明](https://www.tampermonkey.net/faq.php?q=Q209) 启用用户脚本。
3. 更新后的代码会在下次加载游戏页面时运行。正在进行的对局不会被脚本刷新；建议本局结束后再重新打开页面。重复向已运行旧版的页面粘贴新版，不会完成热更新。
4. 打开左侧“设置”：先配置计划、金额与任务开关，然后点“启动”或按 F8。首次安装默认暂停；已有设置会保留。
5. 面板必须显示 **“寻路连接：已连接”** 才能自动移动。连接失败时可点“重新连接”。新版取消了仅按旧构建编号拒绝连接的做法，仍检查实际接口；接口变化时停止移动并显示原因。选卡和移动分别显示，不能以“选择次数增加”判断寻路成功。
6. 标题栏上的“收起 / 展开”始终可用，收起后不会藏进内容区。

F8 暂停会松开脚本按住的键。设置期间暂停脚本操作；游戏本身仍按自己的规则运行。设置存于本浏览器，之后沿用上次启用状态。

## 按当前宝可梦的配置计划选择

先到游戏 **联盟 → 宝可梦 → 配置计划** 配置四个类别：招式、维生素、融合、道具。

- 按当前账号和联盟成员读取游戏已有计划，进化后沿用同一成员计划；不会把吉利蛋的计划用在另一只宝可梦上，也不会改写游戏计划。
- 招式与融合：读取游戏计划和助手内优先名单；先学已计划融合的前置招式并预留空位，再升级材料、完成融合和补齐其他计划招式。相同材料中优先升级离所需等级更近的一项。只有游戏显示就绪且可点击时执行融合。
- 维生素：默认有计划遵循计划，没有计划则优先幸运（星星碎片）。可改为始终按属性、仅计划、完全手动。机变骰子是随机属性，不视为保证增加幸运；明确加入计划/名单才会选。
- 道具：计划、优先名单优先；默认全自动按属性选择、拾取与复制，同属性下参考已装备招式的属性适配。排除道具或满层单件会卖出。可以改为仅计划或完全手动，也可把个别道具加入“交给玩家”名单。
- 未配置招式/融合时不擅自学习或融合。升级没有匹配候选时使用下方无匹配规则；刷新、跳过耗尽或未启用时保持手动。

### 祝福与无匹配规则

祝福默认 **幸运＞伤害＞移动速度＞经验**；四项都未出现时自动选择其他祝福，可调整顺序。

默认允许自动刷新与跳过；每个等级最多自动刷新 3 次，可设置本局刷新/跳过上限、每级刷新上限和尝试顺序。仅点击游戏中还有次数且可用的按钮，不购买刷新次数。

自动放逐默认关闭。启用后只针对明确填写的“可放逐新招式/维生素”名单，依次进入放逐、选中目标、确认。不会自动放逐已装备的招式、计划招式、融合素材或优先维生素；玩家自己进入放逐时脚本等待。放逐与排除不同：排除只是这次不选，放逐会限制本局后续出现/升级。

次数上限 0 表示禁用，留空不额外限制；耗尽游戏剩余次数后保持手动。计数从助手连接本局起算，仅统计助手执行的刷新/跳过/放逐，不追算此前操作。每级上限只计算本等级助手刷新次数，刷新页面后重置；本局累计上限会保留。

### 完整目录和配置

设置内置官网 0.8.59 的 **126 件道具、26 种维生素、919 条招式资料、106 种融合**。招式目录包含客户端全部定义，实际是否可学由当前宝可梦与游戏决定。目录支持搜索、翻页，以及一键加入优先、排除、放逐或手动名单。

进入游戏后读取当前客户端的道具、维生素、宝可梦和招式资料以补全名称/效果；加载失败则使用内置目录。未来游戏新增融合仍需要助手版本更新。资料只用于展示与决策，不修改游戏内容。

全局道具属性初始为幸运＞伤害。可为当前宝可梦单独设置属性顺序，留空继承全局；自动把当前没有使用的物理/特殊伤害类别后移。同一类收益下优先与现有招式属性相符的道具。这些是可配置的路线规则，不代表计算出所有流派的最优解。

旧版设置升级到 3.1 后保留预算、名单与任务开关，道具模式迁移为全自动；如需继续手动，在设置中选择“全部手动”。

## 地图任务与寻路

从本局客户端已生成的地图对象读取位置，根据高度、坡度、树木/岩石等碰撞物、身体半径和已知危险地面规划路线，再通过游戏现有移动键行走。接近后检查实际交互对象，再按 E；不是隔空领取奖励。

异色与捕捉目标仍优先。其他任务可逐个开关，并调整先后顺序：

| 目标 | 自动处理方式 | 必须先配置 |
| --- | --- | --- |
| 未知祭坛 | 跳过尚在封印的祭坛，到圈内驻留充能，完成后处理祝福 | 任务开关、祝福属性顺序 |
| 免费超级球 / 赠球 | 寻路后交互领取，不限次数、不占金额预算 | 免费球开关 |
| 普通精灵球 | 当前价格符合预算才前往、打开 | 普通球预算 |
| 百变怪 | 按当前宝可梦的道具计划/优先名单复制；排除满层道具 | 道具全自动模式，或道具配置 |
| 化石遗迹 | 按预先选择的化石分支交换，随后按道具/祝福/助手规则处理 | 化石交换选项，默认手动 |
| 卡比兽 | 前往并交互，领取游戏给出的奖励 | 卡比兽开关 |
| 融合机器 | 有融合计划、地图对象显示就绪才前往；只执行已计划且可用的融合 | 游戏内融合计划或助手融合名单 |
| 喵喵商店 | 购买符合道具配置且未满层的商品，无合适候选后退出 | 道具配置及独立商店预算 |
| 老虎机 | 每次按实时价格检查预算，等动画与派奖完成后才继续，达到限制退出 | 独立抽奖预算，可加次数上限 |

任务顺序中的 slots 指老虎机。商店不自动刷新货品、不出售已有道具。花费上限、余额限制分别按当前实时余额检查，普通球、商店、抽奖各有独立累计支出。

**化石代价会叠加**：贝壳化石永久最大 HP −15%；甲壳化石 −20%；秘密琥珀在助手入队后 −25%。选择配置即允许每处化石遗迹按该分支交换；未配置不主动前往或交换。

祭坛正在充能时保持驻留，异色等更高优先级目标仍可打断。商店、老虎机和融合机器交互后有冷却，避免立即重复前往；修改设置会清除本地目标冷却。

遇到卡住会跳跃并重算路线，仍无法到达则暂时跳过。高台、必须连续跳跃的平台、复杂动态障碍可能无法通过；不自动迁移地图或重新开局，也不自动触发未启用的机关。关闭自动寻路后，选项处理仍可运行。

## 金额由玩家填写

普通球、喵喵商店、老虎机分别有三个字段，单位为游戏内宝可币 ₽：

| 字段 | 含义 |
| --- | --- |
| 单球 / 单件 / 单次最高价格 | 当前价格超过限制时不买或不抽 |
| 购买 / 抽奖后至少剩余 | 操作后余额低于限制时不执行 |
| 本局总支出上限 | 该类别累计支出加本次价格超过限制时不执行 |

每组金额**初始全部留空**。该组至少填写一项金额才自动消费，其他空白项不限制；0 与留空不同。老虎机还可额外填写本局最多抽奖次数；仅填次数、金额全空时不会自动抽奖。手动打开但尚未配置预算的商店/老虎机保留手动操作。

免费球不受金额限制。脚本连接本局之后的实际开球、商店购买和抽奖也会计入对应账本，包括手动操作；不追算连接前花费。新对局重新计数，地图迁移不重置。

## 捕捉：永久收录和局内助手分开

### 红色精灵球／大师球对应的捕捉流程

当游戏把目标交给永久捕捉流程时，脚本会接近、等待虚弱并投球；异色和经典异色始终优先。普通的可永久收录目标可以在设置中关闭。

脚本使用游戏原有投球流程。是否使用大师球、是否保证成功、是否可永久收录，由游戏自身决定；原流程可能消耗已有的大师球道具。它不会把不可捕捉的普通首领强行变为可捕捉对象。

### 绿色友友球：只在本局战斗的助手

对虚弱的 Alpha 头目，按以下顺序判断：

1. 异色保护优先，不按放弃名单处理异色。
2. “放弃助手名单”中的非异色头目不保留。
3. “优先保留助手名单”中的头目优先保留。
4. 其他目标按所选模式处理：按辅助属性择优、只收名单，或只取免费球掉落。

默认按辅助属性择优，优先幸运和直接伤害。助手辅助效果依据第一属性判断；玩家可调整助手属性排序。队伍有空位时接收，满队时与现有普通助手比较。自动替换时不释放异色随从，也不主动替换已列入保留名单的旧助手；如果没有可替换位置，新助手不入队。

保留／放弃名单支持每行一个中文名称或图鉴编号，例如“皮皮”或“35”。不预填指定宝可梦，由玩家决定。

### 超级球掉落发生在捕捉之前

已核对当前客户端：虚弱头目按 G 放弃捕捉，会走击败头目并掉落免费超级球的奖励流程；捕捉后再从队伍释放，没有这份奖励。

因此，脚本会先判断不需要的头目，再按 G，随后寻找其掉落球。它不会先捕捉再放生并声称能换球。

### 抓到异色后出现“随从替换”

此时图鉴／异色收集已经由游戏记录，弹窗选择的是哪只随从在本局跟随。可选按辅助属性择优、保留旧随从或使用新随从；默认按辅助属性择优。

## 其他范围与验证

- 可开关自动释放终极技、拒绝契约、绕开已知持续伤害地面。
- 游戏暂停、死亡、进入菜单时停止移动；未知弹窗保持手动。
- 自动移动和捕捉限于生存/无尽模式。电脑睡眠、关机、浏览器冻结标签页或游戏自身暂停时，脚本不能继续推进游戏；保持游戏标签页可见效果更稳定。
- 使用官网原始模块的 App 入口读取本局状态，通过键盘与界面按钮操作；不改伤害、血量、金币、概率、存档或后端请求。
- 已核对官网 0.8.59 的模块路径、数据入口、计划存储及升级/放逐界面。保留旧版入口识别；未知构建会注明兼容性未核对，实际接口检查失败时停止自动移动。不能保证未来所有更新都兼容。
- 核心规则测试覆盖预算、计划过滤、任务开关和地形路径；离线浏览器场景覆盖旧版捕捉流程，以及按账号/宝可梦/进化读取计划、无配置招式等手动、融合素材、满层复制限制、化石显式选择、实际移动绕障、祭坛驻留、全套地图任务、商店重绘后连续购买、抽奖动画与金额/次数限制。
- 这些是当前客户端源码核对与本地模拟验证，**尚未在你的账号中实测或完成通宵挂机验证**。

## 自动更新与异常提示停机

脚本设置了 GitHub 固定发布地址的 @updateURL 与 @downloadURL。通过油猴安装后，由油猴按其更新设置检查并安装仓库中版本号更高的发布；控制台临时运行不具备油猴的安装更新机制。未来维护者仍需要核对新游戏版本并发布新的脚本，更新地址不会自动修复代码。

脚本每 5 分钟检查一次游戏官网公开的 version.json，也可点“检查游戏更新”。发现官网新版只提示，不刷新当前对局，以免刷新导致本局结束。游戏接口不兼容时停止自动移动并提示更新。

如果游戏返回账号封禁状态，或页面明确显示账号限制、反作弊警告、未通过服务器校验等提示，停止全部脚本操作并松开移动键，保留游戏原有通知处理；不自动确认或关闭警告。暂停会锁定，需手动核对后重新打开页面再决定是否启用。

这属于可见提示和明确账号状态的响应，不是检测服务器内部反作弊，也不包含规避检测。没有提示不表示脚本获游戏官方许可，不能保证账号或排行榜成绩不受影响。

## 本地测试

核心规则：`node test/core.test.cjs`。离线浏览器场景：安装 Playwright 后运行 `node test/browser.test.cjs`（Windows 默认使用 Edge，其他系统先安装 Playwright Chromium；可用 PLAYWRIGHT_EXECUTABLE_PATH 指定浏览器）。测试会拦截全部网络并使用本地 UI 模拟，不访问真实游戏账号。临时浏览器资料和预览图位于项目目录；本次项目与下载资料全部保存在 D 盘。
